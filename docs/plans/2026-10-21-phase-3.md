**Goal:** Every change to the CV is built, checked and previewed in CI with the same
pinned toolchain as the local machine; releases are versioned, immutable and linkable;
the commit rule is enforced; new evidence turns into approved bullets; and the
repository is proven clean before it goes public.

**Architecture:**
- CI runs the same image as the local machine. Every job builds `tools/Dockerfile` with
  `tools/build.sh` and calls the same `make` targets; workflows only orchestrate
  (checkout, secret file, artifacts, `gh`).
- Jobs that run repository code have a read-only token. Jobs with write scopes
  (PR comment, release) run only `gh` on artifacts or on the gated build.
- The deny-list reaches CI as the secret `CV_DENYLIST`, written to a `0600` file for
  the check steps only. No step prints it; the scripts report entry numbers only.
- Releases are created by CI as **drafts**. Publishing is a human act (Carlos), and a
  second job verifies the published assets.
- The living CV stays local: the `cv-propose` skill reads private sources and writes
  private proposals. Only bullets Carlos approves reach `cv.yaml`, through a PR.

## Global Constraints

- **Approvals.** No commit, push, PR, comment, repository setting, secret, visibility
  change, release publication or LinkedIn change without Carlos' explicit OK for that
  single action. The exact text (commit message, PR title and body, command) is shown
  first, and what is published matches it exactly.
- **No attribution.** No `Co-Authored-By` trailer and no "Generated with" footer, in
  commits, PR bodies, release notes, issues or comments.
- **Commit subjects** match `^(feat|fix|chore): [A-Za-z0-9 ]+$`, one line, no body.
- **Language.** Everything in the repository and on GitHub is in English.
- **Pins.** Every tool and action is at least 2 days old. Actions are pinned by full
  SHA with a version comment. Binaries are pinned by SHA256 in `tools/tools.env`.
- **Nothing on the host.** Every tool runs through `tools/run`. Only tools already on the
  host run outside the container: docker, make, git, gh, sh and curl.
- **Workflow baseline:**
  - top-level `permissions: {}` and the minimal scopes per job;
  - `persist-credentials: false` on every checkout;
  - no `pull_request_target`;
  - no `${{ }}` expressions inside `run:` (values go through `env:`);
  - `timeout-minutes` on every job.
- **Secrets and artifacts:**
  - the deny-list never appears in a log, an artifact or a cache;
  - `make private` never runs in CI;
  - artifacts contain only public build outputs from explicit paths, with
    `retention-days: 14`, because they stay downloadable once the repo is public.
- **CalVer** is `YYYY.MM.DD-NN`, using the date in `America/Sao_Paulo`.

## Review Focus

1. **CalVer in the footer looks like a phone number.** `phone_like("Carlos Apenas · 2026.10.21-01")`
   returns `[1]` today (checked on 2026-10-21), so the first release build would fail
   the public guard. The guard must ignore CalVer strings and still catch a real phone
   on the same line. Tested in Task 2.
2. **A missing deny-list passes silently.** `check_denylist.py` prints a note and skips
   the check when the file is missing. In CI an absent or empty secret must fail the
   job. Tested in Task 2.
3. **A `verify` claim outside the PDF variants.** `meta.verify_count` counts only the
   bullets of one variant, so a `status: verify` on a LinkedIn-only entry would not
   block a release. The release gate scans the whole `cv.yaml`. Tested in Task 2.
4. **Messages that reach `main` without the PR check.** Branch protection and rulesets
   are not available on a private repo in the Free plan (`gh api .../rulesets` returns
   403 "Upgrade to GitHub Pro or make this repository public"). A squash merge writes
   `title (#N)`, a merge commit writes `Merge pull request #N from ...`, and a direct
   push skips the PR. The check rejects both shapes (Task 3), runs again on every push
   to `main` (Task 6), and the repo allows rebase merges only (Task 8).
5. **What turns public with the repository.** GitHub states that "Actions history and
   logs will be visible to everyone" after a private repo becomes public. PR refs
   (`refs/pull/*`) keep commits of closed PRs, and PR comments and artifacts stay too.
   The scanner covers every ref (Task 5); the pre-public scan also covers CI logs,
   artifacts, comments and release drafts (Task 11).

## Deviations from D1–D14 (flagged for review)

- **D9 hooks:** plain git hooks in `.githooks/` (`core.hooksPath`) that call the pinned
  image. The pre-commit framework is not used, because it installs itself and its hook
  environments on the host. CI runs the same checks through `make lint`.
- **D9 tools:**
  - `codespell` from the Debian archive instead of `typos`: the content is prose, the
    package is signed, and it needs one checksum pin less.
  - `check-jsonschema` is not added. `cv.yaml` and JSON Resume are already validated by
    `validate_cv` and `validate_jsonresume` (python3-jsonschema), and actionlint
    validates workflow syntax.
  - gitleaks uses its default rules only. Phone numbers, private values and confidential
    terms stay with `check_denylist.py`, which already has tests and never prints a term.
- **D7 visual diff:** `pdftoppm` plus a small PIL script instead of `diff-pdf`, which
  is not in Debian and would need a wxWidgets build.
- **D7 links:** lychee comes from the same image. Only that command gets network access,
  through `tools/run --net`; `lychee-action` is not used.
- **D8 publishing:** CI creates a draft release, and Carlos publishes it. This keeps
  "every release only with Carlos' OK", and it is GitHub's recommended flow for
  immutable releases (draft → attach → publish).
- **D11 storage:** the research put proposals in the private notes repository
  (2nd-brain-global). Carlos does not want commits there, so decision 2 below settles it.

### Task 2: Release gate, CalVer and check fixes

**Files:**

**Interfaces:**
- `check_denylist.CALVER = re.compile(r"\b\d{4}\.\d{2}\.\d{2}-\d{2}\b")`. It is removed
  from the text before `phone_like` looks for numbers, as `ISO_DATE` is.
- `check_denylist.py --require-denylist`: exit 1 with
  `deny-list required but missing or empty` when the file is absent or has zero entries.
  The Makefile adds it automatically when `CI` is set
  (`$(if $(CI),--require-denylist)`; GitHub sets `CI=true`).
- `check_pdf.version_on_every_page(version: str, text: str) -> list[int]`: the 1-based
  pages, split on `\f`, whose text lacks `version`. The empty piece after the final `\f`
  is ignored. The CLI adds the failure `version <v> missing on page(s) <n,...>`.
- `cvlib.pending_verify(doc: dict) -> list[str]`: the location, such as
  `work[0].highlights[2]`, of every mapping anywhere in the document with
  `status: verify`. Variant tags are not applied.
- `calver.next_version(today: datetime.date, existing: Iterable[str]) -> str`: returns
  `YYYY.MM.DD-NN`, where NN is 1 plus the highest NN among existing names for `today`,
  zero-padded to 2 digits. Names that do not match are ignored. Raises `ValueError`
  above 99.
  - CLI: `calver.py --today YYYY-MM-DD --existing FILE`. It reads a file, not stdin,
    because `tools/run` attaches no stdin.
- `release_gate.py cv.yaml --version V [--report]`:
  - fails when `V` does not match `^\d{4}\.\d{2}\.\d{2}-\d{2}$` or when `pending_verify` is not empty;
  - with `--report`, it prints a one-line Markdown status and always exits 0 (used by the PR comment).
- `release_assets.py`:
  - `asset_names(name: str, tag: str, variants: list[str]) -> dict[str, tuple[str, str]]`:
    `{"backend": ("Carlos-Apenas-Resume-Backend.pdf", "Carlos-Apenas-Resume-Backend-2026.10.21-01.pdf"), ...}`.
    Labels are `{"backend": "Backend", "ai": "AI", "fde": "FDE"}`, and the person's name
    comes from `basics.name` with spaces turned into hyphens.
  - `copy_assets(build_dir, out_dir, name, tag, variants) -> list[str]`.
  - `verify_assets(dir, name, tag, variants) -> list[str]`: the problems found, which
    are a missing or extra file, or a constant file whose bytes differ from its dated copy.
  - CLI: `release_assets.py --copy build --out build/release --tag T` and
    `release_assets.py --verify DIR --tag T`. Both read the name from `cv.yaml` and the
    variants from `--variants` (default `backend,ai,fde`). In `--verify` mode, each PDF's
    `pdftotext` output must also pass `version_on_every_page`.

### Task 3: Commit rule and local git hooks

**Files:**
- Create:
  - `tools/check-commit-msg` (POSIX sh);
  - `.githooks/commit-msg`;
  - `.githooks/pre-commit`;
  - `.codespellrc`;
  - `tests/test_commit_msg.py`.
- Modify: `Makefile` (`lint`, `hooks`), `README.md` (hooks section).

**Interfaces:**
- `tools/check-commit-msg FILE`:
  - drops lines that start with `#`, and everything from git's scissors line `# ------------------------ >8 ------------------------`;
  - drops trailing blank lines;
  - passes only when exactly one line remains and it matches `^(feat|fix|chore): [A-Za-z0-9 ]+$`;
  - on failure, prints the rule and the rejected subject, and exits 1.
- `.githooks/commit-msg`: `exec tools/check-commit-msg "$1"`. It runs on the host, with
  sh and grep only, so it is instant.
- `.githooks/pre-commit`. The staged text files come from
  `git diff --cached --name-only --diff-filter=ACMR`, filtered to text files with
  `git grep -I --cached -l -e '' --`. It runs:
  1. `tools/run gitleaks git --pre-commit --staged --redact --no-banner`;
  2. `tools/run python3 scripts/check_denylist.py --denylist private/denylist.local <staged text files>`;
  3. `tools/run codespell <staged text files>`;
  4. if a `.github/workflows/` file is staged: `tools/run actionlint` and `tools/run zizmor --offline .github/workflows`;
  5. if `cv.yaml`, `skills.yaml` or a file under `template/`, `scripts/`, `schemas/` or `tools/` is staged: `make check` (about 8 s today).
- `make lint`, over the whole tree, as used by CI:
  - `gitleaks git --redact --no-banner`;
  - `codespell` over the tracked text files;
  - `actionlint`;
  - `zizmor --offline .github/workflows`, when that directory exists.
- `make hooks`: `git config core.hooksPath .githooks`, then print the value.
- `.codespellrc` skips `./build`, `./private`, `./schemas/jsonresume-1.3.1.schema.json`
  and `./tests/fixtures`. Words are added to `ignore-words-list` only for a real false positive.

### Task 4: PR preview: page images, text and visual diff

**Files:**
- Create: `scripts/pdf_diff.py`, `scripts/pr_comment.py`, `tests/test_pdf_diff.py`, `tests/test_pr_comment.py`.
- Modify: `Makefile` (`preview`).

**Interfaces:**
- `pdf_diff.compare_pages(base: list[str], head: list[str], out_dir: str) -> list[dict]`:
  - inputs are page PNG paths in page order;
  - returns one `{"page": int, "status": "same"|"changed"|"added"|"removed", "ratio": float, "overlay": str | None}` per page;
  - `ratio` is the fraction of changed pixels (PIL `ImageChops.difference`);
  - pages of different sizes count as changed;
  - `overlay` is the head page with changed pixels tinted red, written only for changed or added pages.
  - CLI: `pdf_diff.py --base-dir D --head-dir D --out D --json FILE`, with pages named `page-<n>.png`.
- `pr_comment.render(variants: list[dict], text_diffs: dict[str, str], gate: str, max_chars: int = 60000) -> str`:
  - each variant dict holds `name`, `pages`, `max_pages`, `previews` (PNG names) and
    `diff` (`compare_pages` output, or `None` when there is no base build);
  - the output starts with `<!-- cv-preview -->`, then:
    - a table (variant, pages/max, changed pages);
    - the release-gate line;
    - `![<variant> page <n>](<file>.png)` previews;
    - overlays for changed pages;
    - one `<details>` block per variant with a fenced `diff` of the text;
  - text diffs are cut so the whole comment stays within `max_chars`, adding
    `Diff truncated; the full diff is in the cv-preview artifact.`
- `make preview`. Base and head are both built with `VERSION=preview`, so the footer
  never shows up as a change. The base build is expected at
  `BASE_BUILD ?= build/base-src/build`. For each variant it runs:
  - `pdftoppm -r 70 -png` for head and base;
  - `pdftotext -raw` for both, then `git diff --no-index --word-diff=plain` into
    `build/preview/<v>.diff` (exit status 1 means "different", not an error);
  - `pdf_diff.py`.

  Then `release_gate.py --report` and `pr_comment.py`, which write `build/preview/comment.md`.

- [ ] `test_identical_builds_report_no_changes`: it shows `No visual or text changes.`

  The report is a Markdown file with counts per source and the findings. Exit 1 on any finding.
