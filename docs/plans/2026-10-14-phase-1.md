**Goal:** A local, self-contained CV-as-code repository where:
- one `cv.yaml` renders three role variants;
- each variant is rendered to a tagged, PDF/UA-1, ATS-clean PDF and to a valid JSON Resume file;
- every output is verified by automated checks, using fictitious data only.

**Architecture:**
- `cv.yaml` is the single source of truth. It uses JSON Resume section and field names, plus small extensions: per-variant values, tags and `status`.
- A Python resolver validates the file against a JSON Schema. It then produces one variant-resolved render model per variant (`build/<variant>/resolved.json`).
- Every output reads that render model: the Typst template, the JSON Resume exporter and the checks. The variant logic exists once.
- Every tool runs in one pinned container image, built from `tools/Dockerfile`, with the dockerized-tools security baseline.

**Tech Stack:**
- Typst 0.15.1, the official musl release binary verified by SHA256.
- Debian trixie-slim, pinned by digest.
- poppler-utils.
- Python 3 from Debian, with `python3-yaml`, `python3-jsonschema` and `python3-pytest`.
- GNU make on the host.

**Spec:** Phase 0 decisions D1–D14, approved 2026-10-14. The research report is kept out of git in `private/research/`.

## Global Constraints

- Nothing is installed on the host. Every tool runs through `tools/run` with this baseline:
  - `--network none`;
  - only `$PWD` mounted as `/work`;
  - `--user` set to the host uid:gid;
  - `--cap-drop ALL` and `--security-opt no-new-privileges`;
  - `--read-only` with `--tmpfs /tmp`.
- Pins:
  - every pinned artifact is at least 2 days old;
  - Typst `v0.15.1` (2026-07-17);
  - `debian:trixie-slim@sha256:a29215f6a35e51e22adffa17f89e9d2ef06214e64a2bad10d765c46aea49f11f` (created 2026-10-05);
  - `@jsonresume/schema` 1.3.1 (2026-07-22), integrity `sha512-S9zH1vmS67b1Ld6p9A+sHiZgqZox4lWTVHtca3VarRVkRtp3C/EMQ2bSNlO39+o+0OZbrY+Srnn7Q8uJOtxZhQ==`.
- Typst runs offline. It uses no Typst Universe packages and `--ignore-system-fonts`, so only fonts embedded in the binary are used.
- PDF output:
  - US Letter;
  - one column;
  - no icon fonts and no small caps;
  - `hyphenate: false` and `ligatures: false`;
  - `document(date: none)`;
  - `--pdf-standard ua-1`.
- `cv.yaml` must never contain a phone number or street address. Private contact data lives only in `private/contact.private.yaml`, which is gitignored and used only by `make private`.
- Checks never print a deny-list term. They report only the entry number and the location.
- Language:
  - everything in the repository is in English;
  - commit subjects match `^(feat|fix|chore): [A-Za-z0-9 ]+$`, one line;
  - no commits without Carlos' explicit OK.

## Review Focus

1. **Tag typo.** A tag that is not a declared variant, such as `fd` instead of `fde`, would silently drop a bullet from every variant. The resolver must fail and name the bad tag and its path. Tested in Task 3.
2. **YAML implicit types.** An unquoted `2023-07-01` becomes a date object, and `NO` becomes `false`. The loader turns dates into ISO strings, and the schema rejects non-string scalars where text is expected. Tested in Task 3.
3. **Private data in the public source.** A `basics.phone` or `basics.location.address` field in `cv.yaml` must fail schema validation. A public build must never contain values from `private/contact.private.yaml`. Tested in Tasks 3 and 6.
4. **Silent PDF degradation.** Any of these must fail the build: hyphenation splitting a bullet, a glyph that falls back to U+FFFD or the private use area, a ligature codepoint, or text in the PDF that is not in the source (hidden text). Tested in Task 6.
5. **Stale toolchain image.** If `tools/Dockerfile` or `tools/tools.env` changes but the image is not rebuilt, the build would silently use the old toolchain. `tools/run` compares the image's hash label with the current files and refuses to run on a mismatch. Tested in Task 1.

## Deviations from D1–D14 (flagged for review)

- **D4 mechanism.** Variants are resolved in Python (`scripts/resolve.py --variant`), not inside Typst through `--input variant=`. Typst receives the already-resolved JSON. The reason: the JSON Resume export and the checks need the same resolution, so it should exist once.
- **D6 layout.** There is a single project image defined inside this repo (`tools/Dockerfile`, which was D6's listed alternative), instead of a `typst` wrapper in dockerized-tools plus a separate check image. The reasons:
  - a public repo must build without a private repo;
  - CI will build the same Dockerfile, which gives exact local/CI parity.

  The wrapper keeps the dockerized-tools baseline word for word.

### Task 3: Data schema and variant resolver

**Files:**
- Create:
  - `schemas/cv.schema.json` (draft-07);
  - `scripts/cvlib.py`;
  - `scripts/resolve.py`;
  - `tests/fixtures/minimal.yaml`;
  - `tests/test_cvlib.py`;
  - `tests/conftest.py` (adds `scripts/` to `sys.path`).

**Interfaces (`scripts/cvlib.py`):**
- `class CVError(Exception)`: carries a human-readable message with a JSON-path-like location.
- `load_cv(path: str) -> dict`: YAML safe-load, then turn date and datetime values into ISO strings recursively.
- `validate_cv(doc: dict, schema_path: str = "schemas/cv.schema.json") -> None`: raises `CVError` listing every schema error. It also checks semantics:
  - every tag and every per-variant key must be a declared variant;
  - every section in `meta.variants.*.sections` must be known.
- `resolve(doc: dict, variant: str, version: str = "dev", private: dict | None = None) -> dict`: returns the render model.
  - Per-variant scalars are resolved: the variant key, else `default`.
  - Entries and bullets whose `tags` exclude the variant are removed.
  - Highlights become `{"text": str, "status": str | None}`.
  - `dates` display strings are added ("Jul 2023 – Present", "2008 – 2011").
  - `sections` becomes an ordered list of `{"key": str, "title": str}`.
  - `meta` holds `{"variant", "version", "title": "<name> Resume", "max_pages", "verify_count"}`.
  - When `private` is given, its `phone` and `email` are merged into `basics`.
- `SECTION_TITLES = {"summary": "Summary", "skills": "Skills", "work": "Experience", "projects": "Projects", "education": "Education", "certificates": "Certifications", "languages": "Languages"}`.
- CLI: `python3 scripts/resolve.py cv.yaml --variant ai --out build/ai/resolved.json [--version X] [--private private/contact.private.yaml]`. It exits 1 on `CVError` and prints the message.

### Task 6: PDF and confidentiality checks

**Files:**
- Create:
  - `scripts/check_pdf.py`;
  - `scripts/check_denylist.py`;
  - `tests/test_check_pdf.py`;
  - `tests/test_denylist.py`.
- Modify: `Makefile` (adds `test` and `check`).

**Interfaces (`check_pdf.py`):** pure functions, plus a CLI `check_pdf.py build/<v>/resolved.json build/<v>/cv.pdf`.
- `parse_pdfinfo(text) -> dict`.
- `parse_pdffonts(text) -> list[dict]`.
- `forbidden_chars(text) -> list[str]`: U+FFFD, U+E000–U+F8FF, U+FB00–U+FB06.
- `missing_bullets(model, text) -> list[str]`: whitespace-normalized substring check.
- `section_order_ok(model, text) -> bool`.
- `extra_tokens(model, text) -> set[str]`: lowercase `\w+` tokens in the PDF text that are not in any string of the model.
- The CLI asserts:
  - pages ≤ `max_pages`;
  - `Tagged: yes`;
  - Title and Author equal to the model;
  - every font `emb=yes` and `uni=yes`;
  - all of the above checks are empty or true.

**Interfaces (`check_denylist.py`):** `check_denylist.py [--denylist private/denylist.local] [--private private/contact.private.yaml] FILE...`
- `load_denylist(text) -> list[Entry]`: one entry per line; `#` starts a comment; `re:` prefixes a regex; other entries are case-insensitive substrings.
- `scan(entries, name, text) -> list[str]`: messages such as `entry #3 matched build/ai/cv.txt:12`, never the term itself.
- `phone_like(text) -> list[int]`: line numbers of candidates with 10 or more digits.
- `private_values_found(private: dict, text) -> list[str]`: reports key names only.
- When the deny-list or private file is missing, it prints a note and skips that check. It does not fail.
